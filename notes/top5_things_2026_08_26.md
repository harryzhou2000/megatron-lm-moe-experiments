## 1. Wrapped up the Sparser MoE optimization stack with new matched results

The main optimization pass for the 2,304-expert, top-36, EP72 latent-MoE workload is now
complete. The route stays compact from radix selection through MCore and HybridEP;
destinations receive only the probabilities they need; permutation skips inactive
experts; and combine and route scanning use the tuned pipeline and bitset paths.

In matched full-model runs with paged stash, full-iteration CUDA graphs, and expert 1F1B,
the complete stack reached:

- **403.7 vs 125.3 TFLOP/s/GPU on GB200** for 2,304E/EP72 (**3.22x**).
- **419.7 vs 127.2 TFLOP/s/GPU on GB300** for 2,304E/EP72 (**3.30x**).
- **421.0 vs 159.4 on GB200** and **435.1 vs 162.2 on GB300** for 2,048E/EP64
  (**2.64x-2.68x**).

A separate 160-iteration MoE-module matrix showed larger gains as routing became a larger
part of the workload: **4.8%** on a Nemotron Ultra proxy, **18.1%** on Qwen397 EP64,
**26.1%** on a sparser Qwen397 proxy, and **106.6%** on the sparse Qwen40 EP72 shape. These
are module-level measurements, not full-model training results.

## 2. Added Kimi K3 Stable LatentMoE support across the GPU stack

The GPU stack now supports the three K3-specific MoE pieces below. This covers the MoE
portion of K3, not the complete model:

The [Kimi K3 MoE note](https://github.com/harryzhou2000/megatron-lm-moe-experiments/blob/945e8fe0091b315e7328111fff9877cab4eb65df/notes/kimi_k3_moe.md) explains the design and math in detail.

- **SiTU-GLU** with the K3 values `beta1=4` and `beta2=25`, native/fused execution,
  and a numerically safe FP32 fallback.

## 3. Added variable-length Qwen3.5 empirical mock-vision replay

A small public JSONL v1 format now replays empirical vision workload shapes without
carrying over private source metadata. Each sample records its complete
`llm_sequence_length` and exactly one vision description (`vision_tokens_per_image` or
`image_sizes`), including explicit text-only samples.

The replay path supports both variable-length packed THD and padded BSHD. THD keeps real
per-sample `cu_seqlens`, separate padded metadata, and a padding mask; mixed and text-only
batches preserve the vision-model execution invariants.

Eight-rank focused tests passed **38 tests per rank**, and a three-step Qwen MoE/GDN EP8
run completed with finite losses and zero skipped/NaN iterations. The isolated work is in
fork-local draft PR
https://.

## 4. Hardened MCore dense routing as a reviewable, backend-safe feature

Dense routing was separated from the broader experimental branch into focused MCore
router, dispatcher, configuration, and test changes. The final path uses TE-selected `[T,K]`
indices only when the selected Flex backend and shape support them, preserves `-1` padded
routes, uses expert-TP-aware dtype limits, and keeps dense metadata independent from the
choice of custom or NCCL all-gather.

Both `dev` and `main` focused suites passed **27/27**, and real eight-rank tests exercised
bool and dense-index HybridEP routing plus dense expert-bias accumulation on every worker.
That closed the correctness and compatibility gaps found during the July rebase. Shapes or
backends that do not support selected indices still use the existing bool-route path.

## 5. Made the many-expert work reproducible and reusable

The legacy 72-GPU Qwen3-Next Sparser MoE launcher was ported into readable model/recipe YAML,
preserving all 115 resolved experiment arguments while separating baseline, paged-stash /
full-CUDA-graph, and expert-1F1B variants.

A single GB200/GB300 performance matrix now covers the 2,304E and 2,048E Qwen3-Next
recipes, Qwen397 variants, Qwen40 Sparser, Nemotron, and K3 with and without QB. The
Sparser MoE work was also consolidated into one technical narrative covering the workflow,
speed-of-light analysis, matched performance stages, and the approaches that did not work:
direct permute, fused combine+unpermute, and warp-pruned scan.

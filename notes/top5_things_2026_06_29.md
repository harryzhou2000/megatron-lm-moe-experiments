## Last Few Weeks (2026/06/08-2026/06/29)

## Decoupled multimodal training

### Qwen3.5 colocated MIMO integration and experiments

MIMO enables module-level heterogeneous parallelism, letting the vision encoder and language model use different logical TP/DP layouts while staying colocated on the same physical ranks.

Integrated a colocated Qwen3.5-VL MIMO path for controlled heterogeneous vision/language layout experiments; 64-GPU results show vision encoder `TP=1` has near-zero overhead versus no-MIMO (**397.85 vs 397.90 TFLOP/s/GPU** on GB200, about **0.8%** overhead on GB300), while vision encoder `TP=8` is about **3.4-3.5%** slower and uses more memory.

### Qwen3.5 MIMO + MDP integration and experiments

MIMO+MDP adds modality-aware workload scheduling, decoupling image encoding ownership from language-sample ownership so variable image counts and sizes can be balanced across vision workers.

Integrated an experimental MIMO+MDP path for variable image count/size workloads; early 8-GPU mock runs show MDP balances visual work correctly but does not yet improve throughput (**211.4 vs 211.1 TFLOP/s/GPU**), so the implication is to first enable a stronger Qwen3.5 `PP + FSDP + EP` baseline and then re-evaluate whether MIMO/MDP is critical for performance.

## Sparse MoE optimizations

Continued Sparse MoE router work in Transformer Engine: [PR #3012](https://github.com/NVIDIA/TransformerEngine/pull/3012) optimizes fused-router forward/backward kernels for large expert/top-k cases, and [PR #3129](https://github.com/NVIDIA/TransformerEngine/pull/3129) adds dense router output for fused router so downstream dispatchers can avoid sparse bool routing-map overhead.
